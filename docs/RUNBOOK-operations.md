# دليل التشغيل — بوابة الفلوس الحقيقية (مرحلة ك)

الأدوات دي بتتعمل قبل ما توصّل يحوّل فلوس حقيقية. كلها متأكّدة محليًا. الجدولة والتشغيل على سيرفر الإنتاج مسؤولية المالك.

---

## ١) الفحوصات الليلية + التقرير اليومي + النسخ الاحتياطي (كرون)

على سيرفر الإنتاج (أو داخل حاوية بيها `DATABASE_URL`)، ضيف الجدول ده بـ `crontab -e`:

```cron
# فحوصات سلامة الفلوس — كل يوم ٢ الفجر
0 2 * * *   cd /app && DATABASE_URL="$DATABASE_URL" npm run invariants   >> /var/log/tewsal-invariants.log 2>&1

# التقرير اليومي — كل يوم ٧ الصبح (بيتبعت واتساب لو WHATSAPP_TOKEN+PHONE_ID+REPORT_PHONE متضبطين)
0 7 * * *   cd /app && DATABASE_URL="$DATABASE_URL" npm run daily-report  >> /var/log/tewsal-daily.log 2>&1

# نسخة احتياطية + بروفة استرجاع + رفع خارجي على R2 — كل يوم ٣ الفجر
0 3 * * *   cd /app && DATABASE_URL="$DATABASE_URL" BACKUP_DIR=/backups npx tsx scripts/backup.ts --verify --upload  >> /var/log/tewsal-backup.log 2>&1
```

- `--verify` بيسترجع النسخة في قاعدة مؤقتة ويتأكد إن الدفتر متوازن (فرق = صفر) — عشان النسخة مش «فاسدة».
- `--upload` بيرفع النسخة على R2 تحت `db-backups/` (محتاج `R2_ACCOUNT_ID` و`R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY` و`R2_BUCKET`).
- `BACKUP_RETAIN` (افتراضي ١٤) بيحدد كام نسخة محلية نحتفظ بيها.
- **نسخة تانية على VPS B**: زوّد سطر `rsync`/`scp` للـ `/backups` على السيرفر التاني، أو خلي VPS B يسحب من R2.

## ٢) أسبوعين تشغيل ظل (شرط التحويل للفلوس الحقيقية)

الفكرة: السيستم يحسب التسويات وإنت لسه بتدفع بالورق/الإكسل، وتقارن **سطر بسطر**. لو طابقوا للقرش **دورتين متتاليتين** → جاهز.

كل يوم تحويل، شغّل:

```bash
# الملخّص لكل تاجر (اللي السيستم هيدفعه لو عملت تسوية بتاريخ القطع)
DATABASE_URL="$DATABASE_URL" npm run shadow -- 2026-09-04

# بالتفصيل لكل شحنة (عشان تطابق أوردر أوردر)
DATABASE_URL="$DATABASE_URL" npx tsx scripts/shadow-settlement.ts 2026-09-04 --detail
```

- التقرير بيستخدم **نفس منطق الأهلية بالظبط** بتاع التسوية الفعلية (`runSettlement`) لكن **قراءة فقط** — مفيش أي كتابة أو دفع.
- التطابق متأكّد بـ `scripts/verify-shadow.ts` (بيشغّل التسوية الحقيقية جوّه ترانزاكشن مرجوعة ويقارن التحصيل/الرسوم/الصافي/العدد — كلهم لازم يطابقوا).
- قارن **صافي المستحق** لكل تاجر برقمك على الورق. أي اختلاف = وقف وحقّق قبل التحويل.

**قاعدة التحويل:** ماتحوّلش فلوس حقيقية إلا بعد **دورتين تسوية متتاليتين** بيطابقوا الورق للقرش، وبعد ما بروفة الاسترجاع تعدّي.

## ٣) اختبار الحمل قبل أي نشر إنتاج

```bash
# المسار العام (تتبع الشحنات) — بدون دخول
BASE=https://<staging> k6 run scripts/loadtest.js

# مع المسار المؤمّن (جدول الشحنات) — محتاج باسورد أدمن staging
BASE=https://<staging> LT_USER=admin LT_PASS='<staging-admin-pass>' k6 run scripts/loadtest.js
```

الأهداف: جدول الشحنات p95 < 300ms · التتبع p95 < 500ms · نسبة الأخطاء < 1%. **لو مش متحققة، ماتنشرش.**

> ⚠️ الدخول محمي بـ rate-limit + قفل حساب ١٥ دقيقة بعد محاولات كتير. السكربت بيسجّل دخول **مرة واحدة** في `setup()` — ماتعدّلوش يعمل login كل iteration.

## المتغيّرات المطلوبة

| المتغيّر | لإيه |
|---|---|
| `DATABASE_URL` | كل السكربتات |
| `R2_ACCOUNT_ID` · `R2_ACCESS_KEY_ID` · `R2_SECRET_ACCESS_KEY` · `R2_BUCKET` | رفع النسخ الخارجية + صور الإثبات |
| `WHATSAPP_TOKEN` · `WHATSAPP_PHONE_ID` · `REPORT_PHONE` | إرسال التقرير اليومي واتساب |
| `SEED_ADMIN_PASSWORD` | باسورد الأدمن على الإنتاج/staging (مش `Admin12345`) |
